# Oracle、证据、结论与归因

## 为什么“没崩”不够

进程存活只能排除一部分灾难。程序可能已经：

- 返回成功但没有生效；
- 留下半初始化状态；
- 重复扣款、重复写入或重复通知；
- 串租户、串设备或继续使用旧对象；
- 泄漏线程、句柄或内存；
- 进入无法恢复的僵尸状态；
- 吞掉错误，直到后续流程才爆炸。

因此每个场景必须选择与声明匹配的 Oracle。

## Oracle 强度层级

| 层级 | Oracle | 示例 |
|---|---|---|
| O1 | 生存性 | 无崩溃、无死锁、无 Sanitizer 报告 |
| O2 | 错误契约 | 错误码、提示、阶段和重试建议正确 |
| O3 | 状态不变量 | 状态迁移合法，失败后处于定义状态 |
| O4 | 资源不变量 | 线程、句柄、队列、内存、临时文件有界 |
| O5 | 数据/权限完整性 | 无半写入、无重复效果、无越权和串数据 |
| O6 | 关系属性 | 幂等、往返、等价、单调性、守恒、前缀关系 |
| O7 | 模型/业务结果 | 实际历史符合参考模型，恢复时间和业务结果达标 |

高风险场景通常至少需要 O3 + O5，并辅以 O1。不要用 O1 代替 O5。

## 常见通用属性

- **幂等性**：相同动作重复执行与执行一次效果一致；
- **往返性**：保存后读取、编码后解码保持语义；
- **失败无副作用**：被拒绝的操作不改变持久状态；
- **单调性**：已确认进度不会无理由倒退；
- **有界性**：资源、重试、队列和日志不会无限增长；
- **隔离性**：一个主体的操作不影响另一个主体的数据；
- **可恢复性**：故障解除后在限定时间内回到稳态；
- **前缀/顺序**：观察到的历史符合承诺的顺序模型；
- **等价性**：不同入口或新旧实现对同一语义输入结果一致；
- **错误透明性**：失败不会伪装成成功或丢失关键原因。

## 扰动落地证据

任何故障或误用都要证明真的发生：

- 网络规则计数器增长，而不是只看到规则已创建；
- 目标进程 PID 变化，而不是只看到 kill 命令成功；
- 磁盘可用空间确实降到阈值；
- 模拟依赖确实返回了预定错误；
- UI 事件确实命中目标应用；
- 回调/消息具有对应序号和时间戳；
- 测试使用的是预期构建、设备、账户和配置。

没有落地证据，只能判定 `INCONCLUSIVE-FAULT-NOT-PROVEN`。


## 结构化执行证据

严格门禁使用以下字段降低“写了一句话就算有证据”的假阳性：

- `Oracle 执行状态`：`EXECUTED / PARTIAL / NOT-EXECUTED`；
- `Oracle 断言总数`：非负整数；
- `Oracle 失败数`：非负整数且不得大于断言总数；
- `扰动命中状态`：`PROVEN / NOT-PROVEN / NOT-EXECUTED`；
- `命中观测来源`：目标端计数器、审计日志、事件序号、PID、资源阈值等独立信号。

`PASS-EVIDENCED` 必须满足：Oracle 已执行、断言数大于 0、失败数为 0、扰动已证明命中。否定性描述如“未采集输出”“没有执行误用”“未能证明命中”不能充当通过证据。

校验器只能验证字段结构和相互关系，不能证明人工填写的日志、计数器或结论真实。

## 结果状态

| 状态 | 使用条件 |
|---|---|
| PASS-EVIDENCED | Oracle 已执行，主要扰动已证明落地，声明未被推翻 |
| FAIL-REPRODUCIBLE | 能稳定重现并已缩减 |
| FAIL-NONDETERMINISTIC | 失败证据真实，但尚不能稳定重现 |
| INCONCLUSIVE-FAULT-NOT-PROVEN | 无法证明扰动作用到目标 |
| PARTIAL-ORACLE | 只验证声明的一部分，或 Oracle 强度不足 |
| BLOCKED-HARNESS | 注入器、驱动、测试脚本或采集器失败 |
| BLOCKED-ENVIRONMENT | 环境、权限、依赖或硬件阻塞 |
| NOT-RUN-SAFETY | 没有授权、回滚或隔离条件，主动不执行 |
| NOT-RUN | 仅用于尚未执行的草稿；严格发布门禁禁止使用 |

## 严格门禁的一致性要求

- `PASS-EVIDENCED`：Oracle、Oracle 输出、扰动落地证据、操作时间线和复现信息必须是实质内容；`无 / N/A / 未执行 / x` 不算证据；
- `FAIL-REPRODUCIBLE`：必须有复现路径或最小复现，以及已捕获的失败证据；
- `FAIL-NONDETERMINISTIC`：必须保存 Seed/操作历史/时间线和真实失败证据；
- `INCONCLUSIVE-FAULT-NOT-PROVEN`：必须分别填写“扰动落地尝试”和“未证明原因”，并使用 `扰动命中状态=NOT-PROVEN`；
- `PARTIAL-ORACLE`：必须写明声明中仍未验证的部分；
- `BLOCKED-HARNESS / BLOCKED-ENVIRONMENT`：Oracle 输出和落地证据可写“未执行”，但必须写明具体阻塞原因和解除条件；
- `NOT-RUN-SAFETY`：Oracle 输出和落地证据可写“未执行”，但必须写明缺失的授权/隔离条件及安全替代执行方式；
- `NOT-RUN`：只能存在于草稿，不能通过严格发布门禁。

使用 `python scripts/validate_campaign.py --strict <campaign.md>` 执行门禁。

## 责任归因

失败或阻塞至少标记一个主要归因：

- `SUT`：产品实现或产品契约问题；
- `HARNESS`：测试驱动、注入器、脚本或数据生成器问题；
- `ORACLE`：检查器错误、过弱或与真实契约不符；
- `ENVIRONMENT`：机器、网络、权限、依赖、设备或版本问题；
- `UNKNOWN`：证据暂时不足，不能武断归因。

## 缩减清单

- 固定版本、配置和 Seed；
- 把输入缩到最小字符、字段或数据项；
- 把操作历史缩到仍失败的最短子序列；
- 减少客户端、线程、节点或重复次数；
- 缩窄故障窗口；
- 去掉一个复合扰动；
- 用独立 Oracle 复核；
- 在干净环境重跑；
- 保留原始证据，避免清理脚本覆盖现场。

## 回归测试证明

一个回归测试只有在以下条件满足时才算有效：

1. 在带缺陷版本上确实失败；
2. 在修复版本上通过；
3. 断言指向缺陷承诺，而不是偶然实现细节；
4. 失败消息能定位问题；
5. 必要时故意重新引入缺陷或使用 Mutation，确认测试会再次失败。


## 发布结论一致性

严格门禁不仅校验场景格式，还会解析全局安全与发布结论：

- `PASS`：每个声明关联的所有场景均为 `PASS-EVIDENCED`，不存在失败、阻塞或部分 Oracle；未验证声明和阻塞项必须为无，且 `环境恢复状态=RESTORED`；
- `CONDITIONAL-PASS`：不得存在确认失败或环境/工具阻塞，必须明确剩余风险；
- `BLOCKED`：必须存在阻塞场景或具体阻塞项；
- `FAIL`：必须至少存在一个 `FAIL-*` 场景；
- 已验证声明与未验证声明必须无重叠并完整覆盖声明清单；只有关联场景全部为 `PASS-EVIDENCED` 的声明才能列为已验证；
- 声明 ID 必须精确解析，拒绝子串、重复和未知引用；
- 安全章节必须包含隔离、禁止操作、停止、恢复、证据分级、脱敏、访问、保存和导出复核。
