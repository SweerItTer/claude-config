# 缺陷归因与结果分类

## 责任分类

- `SUT`：被测系统的实现、配置或产品声明存在问题；
- `HARNESS`：驱动器、注入器、测试脚本或收集设施错误；
- `ORACLE`：断言不完整、错误或存在竞态；
- `ENVIRONMENT`：环境不满足前置条件，或环境自身异常；
- `UNKNOWN`：证据不足，暂时无法归因。

不要为了关闭问题而过早归因。归因必须附证据和可反驳条件。

## 常用结果状态

| 状态 | 含义 |
|---|---|
| `PASS-EVIDENCED` | 扰动已证明生效，Oracle 已执行并通过 |
| `FAIL-REPRODUCIBLE` | 有稳定复现路径 |
| `FAIL-NONDETERMINISTIC` | 异常已捕获，但复现不稳定 |
| `INCONCLUSIVE-FAULT-NOT-PROVEN` | 无法证明故障或误用真正作用于目标 |
| `PARTIAL-ORACLE` | 只验证了声明的一部分 |
| `BLOCKED-HARNESS` | 测试设施阻塞 |
| `BLOCKED-ENVIRONMENT` | 环境阻塞 |
| `NOT-RUN-SAFETY` | 因授权或破坏边界未执行 |

## 假成功识别

以下情况不能写 PASS：

- 测试命令退出码为 0，但没有业务 Oracle；
- 故障注入命令执行成功，但目标未受到影响；
- 进程仍存活，但状态、数据或资源已经异常；
- 重试最终成功，但过程中产生重复副作用；
- 日志出现预期字符串，但实际状态未改变；
- 随机活动没有崩溃，却没有结束健康检查。
